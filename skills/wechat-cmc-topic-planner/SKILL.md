# 信使引擎选题策划

为“信使引擎”发现、筛选和排序可审核的技术选题。论文型候选必须通过跨报告 DOI 唯一性硬门槛；主题和角色可以重复。默认用中文 Markdown，并保存到项目根目录的 `reports/topics/`。

## 必读规则

开始前读取：

1. `references/account-profile.md`
2. `references/content-baseline.md`
3. `references/relevance-scoring.md`
4. `references/topic-scoring.md`
5. `references/doi-dedup.md`

仅在首次校准、规则存在争议，或模型对边界评分不确定时读取 `references/calibration-cases.md`。需要计算双轴关联分和后续动作时运行 `scripts/calculate_relevance.py`。每次选题开始和保存报告后运行 `scripts/manage_doi_ledger.py` 维护跨报告 DOI 台账。

查找项目根目录 `reports/diagnosis/` 中最新的诊断报告，并优先使用统计周期完整且最接近当前日期的版本。若报告不存在、过旧或缺少文章级转化数据，继续工作，但在“本次依据”和“数据缺口”中明确说明。

## 工作模式

根据用户意图选择模式：

- **扫描模式**：先发现候选，再评分。用户提供主题、产品、工艺环节或时间范围时按该范围检索；未提供时覆盖 mRNA CMC、LNP 递送、体内 CAR-T、靶向递送、circRNA 和 saRNA。
- **评估模式**：只评估用户提供的标题、摘要、全文、专利或政策材料。不要擅自扩大检索范围；证据不足时明确列出补齐材料。

两种模式共用同一评分和输出规则。

## 候选发现

默认检索最近 9 个月。监管政策不设硬时间窗，但必须检查是否已被替代或失效；用户给出的时间范围优先于默认值。

来源优先级：

- **A级**：同行评审论文、正式法规和监管政策、可核验的专利全文。
- **B级**：预印本、会议摘要、临床试验注册、公司技术文档。
- **C级**：行业媒体和公司宣传，只作为回查原始资料的线索。

扫描模式先召回 30-60 条原始记录。规范化标题、来源、日期、对象和主题后，去除同一事件或同一研究的重复报道；同一 DOI 在本次召回中只保留信息最完整的一条。候选仍需通过跨报告 DOI 唯一性检查，保留 15-20 条进入完整评分，最终最多输出 10 条决策卡。

搜索时组合技术模态、工艺或质量环节、变量或异常、验证或控制动作，不要只使用用户原话。没有明确来源、日期或研究对象的内容不得进入正式候选池。

## 必过门槛

每条候选必须能写成一句“工艺/质量决策句”：

`在 [对象或环节] 中，[变量或异常] 会如何影响 [结果]，读者应如何验证或控制？`

句子必须包含可执行的技术判断，例如工艺参数、CQA/CPP、分析方法、可比性、稳定性、纯度或控制策略。只报告机制、临床终点、融资、管线或公司进展的内容不通过；只有在其明确改变 CQA/CPP 理解、分析方法设计或工艺控制策略时才可作为例外。

无法形成决策句的内容标为“背景”，不得进入正式选题池。

## 筛选流程

严格按以下顺序执行：

1. 运行 `scripts/manage_doi_ledger.py sync --project-root <项目根目录>`，建立最新跨报告 DOI 台账。
2. 来源扫描或读取用户材料，提取标题、来源、日期、研究对象、DOI 和关键原文片段。
3. 规范化候选并按 DOI 去除本次批次内的重复条目。
4. 写出“工艺/质量决策句”，执行必过门槛。
5. 对论文型候选运行 `scripts/manage_doi_ledger.py check`。已使用的 DOI 标记 `重复禁发` 并淘汰；没有可核验 DOI 的文献候选标为背景。
6. 按 `references/relevance-scoring.md` 分别给出 mRNA CMC 轴和 LNP 递送轴 `0-4` 分。
7. 运行 `scripts/calculate_relevance.py` 计算关联分、关联等级、证据等级和允许动作。
8. 对仍符合条件的内容执行主题级历史排重；主题命中允许保留，但必须说明新增证据或不同决策场景。
9. 按 `references/topic-scoring.md` 计算综合选题分。
10. 对准备写入决策卡的最终 DOI 列表再次运行 `check --fail-on-duplicate`；只要出现重复，就删除对应候选，不得写入正式选题池。
11. 输出决策卡，并按综合分排序；保存报告后再次同步 DOI 台账。

关联度决定内容是否属于主线，综合分决定本周是否值得发布。两者不得合并成一个总分，也不得用综合分挽救未通过关联门槛的内容。

## DOI 与历史排重

DOI 唯一性是论文型候选的硬门槛，主题级排重是软约束。评分前必须先运行 DOI 台账检查；台账覆盖历次 `reports/topics/` 决策卡中的来源 DOI。详细操作读取 `references/doi-dedup.md`。

- `新问题`：DOI 在台账中不存在，且历史文章没有回答同一个研发决策问题。
- `同主题新文献` 或 `可续写`：DOI 在台账中不存在，但主题、角色或工艺环节与历史内容相同；允许进入选题池，文章应使用新论文的证据、方法或案例形成不同验证路径。
- `重复禁发`：论文 DOI 已存在于台账，或本次批次出现同一 DOI；关联分和综合分均不能挽救。
- 法规政策和专利不使用 DOI 检查，但仍须按政策编号、专利号或其他稳定标识排重。

主题命中本身不得成为论文型候选的淘汰理由。无法确认历史文章全文覆盖时，说明主题级排重范围，不得声称完成全量排重；DOI 台账覆盖范围则以 `doi-ledger.tsv` 和扫描到的报告为准。

## 决策卡

每题输出以下字段：

| 字段 | 要求 |
| --- | --- |
| 候选标题 | 保留原文标题，可附中文直译 |
| 来源信息 | 来源类型、发布日期、DOI/专利号/政策编号或 URL |
| 工艺/质量决策句 | 必须通过必过门槛 |
| DOI 唯一性 | `唯一：可进入评分`、`重复：已淘汰`，或法规/专利的对应稳定标识检查结果 |
| mRNA CMC 关联 | 分数、判定理由和原文证据片段 |
| LNP 递送关联 | 分数、判定理由和原文证据片段 |
| 关联结果 | 关联分、双核心/核心候选/桥接候选/淘汰、置信度 |
| 证据结果 | A/B/C 等级、证据分和核验限制 |
| 排重状态 | 新问题、同主题新文献、可续写或重复禁发 |
| 不确定性与缺口 | 信息不足、冲突或需要补齐的材料 |
| 最终动作 | 立即深挖、进入选题池、持续追踪或淘汰 |

每条高分必须有原文证据片段，不能只给概括性理由。信息不足使用 `X`，不得猜测后补全。

## 综合选题与输出

通过关联门槛的内容再按 `references/topic-scoring.md` 获得综合选题分，最终最多保留 10 题。优先结构为：

`异常现象 -> 原因判断 -> 验证路径 -> CMC 决策`

前 3 题给出文章大纲，包含研发问题、异常现象、原因假设、验证路径、CMC 决策边界和证据要求。除非用户明确要求，不生成可直接发布的全文。

输出开头列出统计周期、数据来源、扫描范围、候选数量、DOI 台账扫描结果和排重覆盖。保存结果时使用 `reports/topics/YYYY-MM-DD-关联度筛选.md`；若同日已有文件，在文件名末尾增加主题短名，不覆盖历史报告。报告保存后再次运行 `scripts/manage_doi_ledger.py sync --project-root <项目根目录>`，把本次决策卡中的 DOI 写入台账。

## 证据与合规边界

- 分开标注同行评审、法规政策、专利、预印本、会议材料、公司材料和编辑判断。
- 不编造论文、数据、法规要求、专利状态、后台指标或引用链接。
- 不编造或猜测 DOI；无法核验 DOI 的文献候选不得进入正式决策卡。
- 不把摘要中的推断写成全文已证实结论。
- 不请求、保存或输出密码、Cookie、token、客户信息或企业保密材料。
- 不把历史阅读表现写成单篇内容的因果结果。
